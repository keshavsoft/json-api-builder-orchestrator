The Blueprint of the API

The Story of api.json

Everything in JSON API Builder starts with api.json. It acts as the single source of truth that defines routing paths, CRUD endpoints, database mock files, port bindings, and custom operational strategies.

test/v1/input/api.json
Input File 
{
  "root": "api",
  "port": 3000,
  "routes": {
    "v1": {
      "clinics": {
        "resource": "clinics",
        "idField": "id",
        "endpoints": [
          { "method": "GET",    "path": "/",    "operation": "list" },
          { "method": "POST",   "path": "/",    "operation": "create" },
          { "method": "GET",    "path": "/:id", "operation": "read" },
          { "method": "PUT",    "path": "/:id", "operation": "update" },
          { "method": "DELETE", "path": "/:id", "operation": "delete" }
        ],
        "dataFile": "data/clinics.json"
      }
    }
  },
  "strategies": {
    "fs": {
      "file-sync": {
        "method": "GET",
        "path": "/file-sync",
        "dataFile": "data/players.json"
      }
    }
  }
}

The 4 Key Elements of the Story

How each key directly translates into server infrastructure

1. Global Runtime Config ("root", "port")

Specifies the primary mount namespace (/api) and listening port (3000). Used by json-api-builder-create-app to initialize the Hono HTTP server instance.

2. Hierarchical Routers ("routes.v1.clinics")

Defines nested route structures. json-api-builder-alter-content walks this hierarchy to wire child routers into parent routers automatically without manual imports.

3. REST Endpoints & Data File

Declares standard HTTP verbs (GET, POST, PUT, DELETE) and links them to data/clinics.json. json-api-builder-create-endpoints generates full CRUD handlers referencing this JSON database.

4. Operational Strategies ("strategies.fs")

Extensible capabilities outside standard REST. Here, file-sync mounts /fs/file-sync, allowing clients to stream or fetch local datasets like data/players.json directly.

How api.json Flows Through the Stages

See how each stage consumes parts of the specification

Stage 0: Validation
Validates that api.json contains valid methods, paths, and referenced dataFiles exist.
Stage 1: Create Folders
Builds api/v1/clinics and endpoints/fs directory paths.
Stage 2: Create Files
Creates skeleton files for route modules and copies mock JSON data.
Stage 3: Insert Content
Injects AST route boilerplate into all generated route files.
Stage 4: Alter Content
Chains clinics router into v1 router, and v1 into root.
Stage 5: Create App
Creates app.js, binds port 3000, and mounts /api.
Stage 6: Create Endpoints
Generates handlers for list, create, read, update, delete & file-sync.
Stage 7: Verify
Ensures all endpoints and route files match specification exactly.
